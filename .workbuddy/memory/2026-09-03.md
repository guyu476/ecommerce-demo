## 推送 ecommerce-demo 到 GitHub（guyu476/ecommerce-demo）

- 目标仓库：`guyu476/ecommerce-demo`（最初为 Private，用户后改为 Public）。
- 结论：本环境无法直接 `git push`，原因是：
  1. 沙箱内 git 连 `github.com:443` TCP 超时（关沙箱后网络通）。
  2. 全局 `credential.helper` 路径写错了——原指向 `C:/Users/Lenovo/.workbuddy/vendor/PortableGit/.../git-credential-manager.exe`（目录不存在），已改为正确路径 `C:/Users/Lenovo/.workbuddy/binaries/PortableGit/versions/1.2.0/mingw64/bin/git-credential-manager.exe`。
  3. 该 GCM 在无 TTY 环境下 `get` 会段错误（exit 139），无法弹浏览器登录。
- GitHub MCP（connector）只有 public_repo 权限，仓库 Private 时 404；改 Public 后可读（`list_commits` 返回 409 empty）。
- MCP `push_files` 不适用的原因：需内联 43 万字节（package-lock.json 27 万字节）、二进制 favicon.ico 传不了、且会把 8 条 commit 压平并分叉。
- 最终方案（用户选择「手动上传」）：用 `git archive HEAD | tar -x` 导出 62 个受控文件到 `D:\ecommerce-demo-github-upload`，用户拖到 GitHub Web「Upload files」。
- 本地 9 条 commit（含新增 `chore: gitignore .upload-manifest.json`），工作区干净。
- 未跟踪 `.upload-manifest.json` 已加入 .gitignore。
